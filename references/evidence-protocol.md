# 证据协议

## 1. 证据等级

根据分析阶段使用下面两套等价标签，整份交付保持一致：

| 通用标签 | 旅程/Agent阶段可用标签 | 判断标准 |
|---|---|---|
| 【已确认】 | 【页面事实】/【事实规则】 | 页面、截图、公开聊天、可见资产、状态、工具结果或官方资料直接支持 |
| 【合理推断】 | 【合理推断】/【推断规则】 | 多条事实共同支持，但后台实现或字段不可见 |
| 【建议设计】 | 【建议规则】 | 为可靠性、完整性或可运营性提出的改进，不代表产品现状 |
| 【未知】 | 【尚未确认】 | 证据不足，存在多个同样合理的解释 |

不得仅凭行业惯例把“合理推断”升级为“已确认”。

## 2. 证据编号

使用稳定编号，例如 `E01`、`E02`。每条证据至少记录：

- 时间顺序或截图编号
- 来源类型：用户操作、聊天、Agent 名称、按钮/表单、工作区产物、历史版本、模型选择、工具结果、权限、安全、错误、计费、官方资料
- 页面原文或可见内容
- 组件、数据对象或产物名称
- 可直接支持的结论
- 访问限制或歧义

同一截图可支持多条事实，但不要用一个宽泛编号替代精确说明。

## 3. 取证顺序

1. 从最早一条用户输入开始。
2. 记录原始目标、约束、用户输入、上传材料、数据来源、权限选择和表单配置。
3. 记录产品第一次回应、Agent 身份、公开计划和确认问题。
4. 对每次用户确认或修改，检查聊天、任务卡、工作区、结构化数据、产物和执行状态分别发生了什么。
5. 检查满意继续、修改、换方案、中断、返回、重试入口是否真实可见。
6. 检查正常执行、失败、安全拦截、权限不足、额度不足、用户中断和状态写入失败是否真实出现。
7. 检查最终产物、预览、编辑、导出、部署、发送、分享或发布入口及真实可用状态。最终产物可为代码、应用、报告、文档、数据集、查询结果、业务记录、图片、视频、音频或其他领域对象。

## 4. 冲突记录

发生以下情况时建立“状态冲突记录”：

| 字段 | 说明 |
|---|---|
| 冲突对象 | 聊天、任务、工作区、产物库、执行结果、预览、权限、计费或其他 |
| 事实 A | 来源与证据编号 |
| 事实 B | 来源与证据编号 |
| 用户影响 | 用户无法判断完成、可能重复操作或产生额外费用等 |
| 当前结论 | 保持冲突，不自行裁决 |
| 建议验证 | 需要查看的状态、日志、资产或交互 |

## 5. Agent 与工具证据

- 只有页面出现名称或明确身份时，才把它列为实际 Agent。
- “接下来我会生成”是计划，不是工具调用证据。
- 产物出现、任务状态变化、调用结果或错误返回可证明某种功能动作发生，但通常不能证明官方函数名。
- 功能性工具命名采用动宾结构，例如“读取项目上下文”“修改代码文件”“执行数据查询”“生成媒体产物”“写入任务状态”，并标记非官方名称。
- 不尝试恢复隐藏 Prompt、内部路由代码或模型思维链。

## 6. 外部资料

- 用户要求时或页面证据不足且需要外部补充时，优先使用目标产品官方站点、官方文档、官方帮助中心和官方公告。
- 第三方文章可作为线索，不作为当前架构事实。
- 官方营销描述只证明官方声称的能力；若与页面行为不一致，保留差异。
- 不采集或输出 Cookie、Token、密码、鉴权头和个人敏感信息。
