# 最终交付与验收门

## 唯一交付物

完整产品架构分析默认只交付一份最终 HTML，文件名使用稳定的英文短横线格式，例如 `product-architecture-analysis.html`。文件必须自包含，不依赖其他阶段报告才能理解核心结论。

章节内容按 [report-contract.md](report-contract.md) 执行，交互与导出按 [interactive-report-spec.md](interactive-report-spec.md) 执行。

## 必备图表库

完整报告至少检查是否需要以下图表。不适用或证据不足时不强行生成，但必须在证据缺口或未知项说明。

| 图表 | 作用 | 默认形式 |
|---|---|---|
| 用户旅程图 | 正常、修改、失败和中断路径 | 三泳道 Mermaid flowchart |
| Agent 协作图 | 输入、判断、工具、输出与交接 | Mermaid flowchart |
| 状态机 | 等待、确认、执行、校验、失败、重试、中断、完成 | Mermaid stateDiagram-v2 |
| 依赖/失效图 | 上游修改对下游产物的影响 | Mermaid flowchart/DAG |
| ER 图 | 核心实体与关系 | Mermaid erDiagram |
| 端到端时序图 | 用户、Agent、工具、状态和产物的交互顺序 | Mermaid sequenceDiagram |
| 产品全景架构主图 | 分层组件、数据、状态和风险 | Mermaid flowchart 或同源 SVG |

每张 Mermaid 图都必须附完整、可见、可选中的源码，并提供一键复制和 `.mmd` 下载。

## 主架构图约束

- 从上到下分层，同层组件置于同一 `subgraph`。
- 边标注“调用、读取、写入、事件、确认、产物引用、状态更新”等语义。
- 实线表示已确认，虚线表示合理推断，特殊颜色或点线表示建议设计，并提供图例。
- 显式标记状态冲突、缺失校验、失效机制和当前阻塞点。
- 关键节点附证据编号或证据等级。
- 静态 SVG 若与 Mermaid 并存，两者必须来自同一份语义源。

## 交付流程

1. 完成证据编号和分级，再写结论。
2. 按内容契约生成全部章节，不用“见另一份报告”取代核心内容。
3. 复用 `assets/report-template.html` 的交互外壳，填入实际内容。
4. 在浏览器中检查目录、表格、小屏、图源码、筛选、复制、导出和打印。
5. 运行 `python3 scripts/validate_report.py <report.html>`，修复所有错误。
6. 最终回复提供报告的可点击绝对路径和验证结果。

## 完成门

只有以下项同时满足才能声称最终报告完成：

- 一份 HTML 内包含完整分析，无未替换占位符。
- 事实、推断、建议和未知没有混写，事实冲突未被掩盖。
- 关键结论可回跳证据，证据能指向所支持结论。
- 图源码可复制、可下载，长表可导出，整体可打印/另存 PDF。
- Mermaid 失败时，源码和文字/表格仍能表达核心信息。
- 自动校验通过，且至少做过一次浏览器视觉检查。
- 文件位于用户可访问目录，最终回复提供绝对路径 Markdown 链接。
